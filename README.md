# ПОС - преподавательская оценка студентов

Домашнее задание №2 по КПО Python 3.10+, Ports and Adapters, DDD,
три паттерна проектирования и контейнер `dependency-injector`

## Запуск

Команды выполняются из папки проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python main.py
```

В Windows вместо активации можно запускать `.venv\Scripts\python.exe main.py`
Альтернативная точка входа - `python -m pos`

Программа начинает работу с пустой ведомостью, если хранилища еще нет
Каждая успешная операция сохраняется в `data/gradebook.json` При следующем запуске
студенты, критерии и оценки восстанавливаются Другой файл задается через
`python main.py --data data/another.json`

## Команды

| Команда | Назначение |
| --- | --- |
| `student ID "Имя"` | Добавить студента |
| `criterion ID "Название" МАКС ВЕС` | Добавить критерий |
| `students`, `criteria` | Посмотреть студентов и рубрикатор |
| `grade СТУДЕНТ КРИТЕРИЙ БАЛЛ` | Выставить оценку или заменить существующую |
| `cancel СТУДЕНТ КРИТЕРИЙ` | Отменить оценку |
| `grades СТУДЕНТ` | Посмотреть оценки студента |
| `total СТУДЕНТ [all\|graded]` | Получить итог из 10 |
| `report [all\|graded]` | Получить итоги всей группы |
| `export "Путь.csv" [all\|graded]` | Выгрузить итоги в CSV |
| `help`, `quit` | Справка и выход |

Строки с пробелами заключаются в двойные кавычки Десятичные числа принимают точку
или запятую Идентификаторы чувствительны к регистру, крайние пробелы удаляются
Для путей в Windows в командах консоли используйте прямой слеш: `C:/temp/results.csv`
После ошибочной команды можно продолжать работу EOF и Ctrl+C завершают ввод

## Демонстрация

```bash
python main.py --data data/demo.json --script examples/demo.txt
```

Для первого прогона файл `data/demo.json` должен отсутствовать Для повторного
запуска используйте новое имя хранилища, например `--data data/demo2.json`:
повторное добавление тех же идентификаторов намеренно отклоняется

Сценарий создает двух студентов и два критерия, показывает списки, выставляет
оценки, исправляет и отменяет оценку, сравнивает два режима итога, восстанавливает
оценку и экспортирует ведомость в `results.csv` в текущей папке
Итоги: Анна - **7.80**, Иван - **6.20** После отмены экзамена у Ивана итог по всем
критериям - **2.00**, предварительный по выставленным оценкам - **5.00**
Все демонстрационные данные находятся в файле, а не в коде приложения

Код завершения: `0` - штатная работа; `1` - в файле команд были ошибки;
`2` - файл ввода нельзя открыть или прочитать В интерактивном режиме исправимые
ошибки команд не меняют код штатного выхода

## Правила расчета

Итог рассчитывает доменный сервис `TotalCalculator`, без сохранения устаревающего
числа в студенте или ведомости:

```text
итог = 10 × сумма((балл / максимум критерия) × вес) / сумма(весов)
```

Вес - положительное число; сумма весов не обязана быть равна единице
Например, 15/20 с весом 2 и 8/10 с весом 3 дают 7.8 из 10

- `all` - основной режим: в знаменателе весь рубрикатор, пропущенные оценки
  дают нулевой вклад Без выставленных оценок итог равен нулю
- `graded` - предварительный результат: в знаменателе только оцененные критерии
  Если оценок еще нет, выводится «нет оценок», а в CSV - пустое поле

В обоих случаях сохраняется взвешенная формула При пустом рубрикаторе расчет
итога студента отклоняется В отчете указано число выставленных оценок и критериев;
CSV также содержит режим расчета Баллы и веса представлены `Decimal`
Округление до двух знаков применяется только при отображении и экспорте,
по правилу `ROUND_HALF_UP`

## Карта DDD

| Элемент | Реализация и ответственность |
| --- | --- |
| Ubiquitous Language | `Student` - студент, `Criterion` - критерий, `Evaluation` - оценка, `Gradebook` - ведомость, `Total` - итог |
| Entity | Студенты и критерии имеют устойчивый `id`; одинаковые имена разрешены, повтор одного идентификатора запрещен |
| Value Object | Неизменяемый `Score(value, maximum)` сравнивается по значениям и проверяет диапазон; `Evaluation` заменяется целиком при исправлении |
| Агрегат | `Gradebook` содержит студентов, рубрикатор и оценки одного курса и контролирует ссылки между ними |
| Repository | Порт `GradebookRepository` в Application загружает и сохраняет агрегат целиком |
| Domain Service | `TotalCalculator` объединяет оценки и веса критериев; итог каждый раз рассчитывается по текущему состоянию |

В [model.py](pos/domain/model.py) балл ограничен диапазоном `[0, maximum]`;
максимум и вес строго положительны; бесконечности, NaN и пустые имена запрещены
Фабрика проверяет существование студента и критерия Сам агрегат дополнительно
проверяет ссылки и соответствие шкалы при записи оценки, поэтому обход фабрики
не позволяет записать оценку по чужому рубрикатору Пара идентификаторов
студента и критерия однозначно определяет место оценки в ведомости

Списки выдаются кортежами, их элементы неизменяемы Исправление оценки заменяет
предыдущую запись; неудачное исправление сохраняет прежнюю оценку
Добавление нового критерия сразу влияет на итог в режиме `all`
Изменение и удаление студентов/критериев не реализованы: ТЗ оставляет их
необязательными; это исключает неоднозначность пересчета уже выставленных оценок

Один агрегат на курс выбран для небольшого локального приложения: правила ссылок
и изменения оценок контролируются в одном месте Для нескольких курсов потребуются
идентификаторы курсов и отдельные экземпляры агрегата Пересдачи и апелляции пока
не моделируются

## Архитектура Ports and Adapters

```text
Console → AssessmentFacade → Gradebook, EvaluationFactory, TotalCalculator
                        ↓
       GradebookRepository, ResultsExporter (порты)
                        ↑
          JsonRepository, CsvExporter (адаптеры)
```

- `pos/domain/`: сущности, объекты-значения, агрегат и расчет итогов Только
  стандартная библиотека; нет файлов, консоли или DI-фреймворка
- `pos/application/`: сценарии и интерфейсы внешних зависимостей Импортирует Domain
- `pos/adapters/`: JSON-хранилище, CSV-экспорт и консоль Импортирует внутренние слои
- `pos/container.py`: composition root, который соединяет порты с реализациями
  `pos/__main__.py` разбирает параметры запуска и передает потоки консоли

Зависимости исходного кода направлены внутрь: Adapters → Application → Domain
Интерфейсы хранилища и экспорта принадлежат Application, реализациям не нужно
передавать контейнер внутрь домена Прямое связывание через контейнер находится
только на краю приложения

`JsonRepository` преобразует JSON обратно через доменные конструкторы и фабрику,
поэтому поврежденный файл не обходит инварианты Изменения записываются во временный
файл рядом с хранилищем и затем заменяют основной файл При ошибке записи исходная
ведомость сохраняется Репозиторий возвращает отдельный снимок агрегата; фасад
сохраняет его только после успешной операции Приложение рассчитано на один
пишущий процесс; блокировки для параллельного редактирования не реализованы

Экспорт выполняется через порт `ResultsExporter` CSV использует UTF-8 с BOM,
сохраняет имена с запятыми и запрещает запись поверх активного JSON-хранилища
Существующий файл CSV заменяется; каталог назначения должен существовать

## Паттерны

| Группа | Паттерн | Где и зачем |
| --- | --- | --- |
| Порождающий | Фабрика | `EvaluationFactory.create` проверяет принадлежность студента и критерия ведомости и создает `Score` по правильной шкале Используется при выставлении оценок и восстановлении JSON |
| Структурный | Фасад | `AssessmentFacade` объединяет загрузку, доменную операцию, сохранение, расчет и экспорт Консоль вызывает готовые сценарии, не управляет файлами или агрегатом |
| Поведенческий | Стратегия | `AllCriteria` и `GradedCriteria` задают состав критериев для `TotalCalculator` Позволяют сравнивать полный и предварительный итоги без копирования формулы в UI |

Используется ровно по одному паттерну из каждой группы Фабрика здесь - простая
фабрика из разрешенных в задании примеров; наследование ради Factory Method
не добавляется DTO, универсальные CRUD-сервисы и отдельный класс для каждой команды
не нужны для текущего масштаба

## DI и проверки

`Container` из `dependency-injector` создает репозиторий через `Singleton`, а фасад,
фабрику, экспортер, стратегии и калькуляторы - через `Factory`
В тестах порт хранения заменяется на `MemoryRepository`, экспортер - на mock
через `provider.override`, без изменения сценариев

```bash
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
python -m coverage run -m unittest discover -s tests
python -m coverage report -m
python -m ruff check .
python -m ruff format --check .
```

Тесты проверяют границы баллов, ссылки, дубликаты, неизменяемость, оба режима
расчета, исправление и отмену оценок, изменение рубрикатора, сохранение и загрузку,
поврежденные файлы, отказ записи, CSV, подмену зависимостей и сквозной сценарий CLI
